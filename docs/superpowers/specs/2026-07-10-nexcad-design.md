# NexCAD 設計規格

日期：2026-07-10
狀態：已與用戶確認

## 1. 概述

NexCAD 是一款給 Maker 和學生使用的 Web App，用來製作創科（STEM）專案的 3D 工程件，最終輸出給 3D 印表機列印。核心差異化：**零件優先工作流** — 用戶先放入電子零件（Arduino、ESP32、感測器等），系統根據零件的設計資訊自動產生外殼、螺絲孔和支柱，再用基本形狀與 boolean 運算微調。

## 2. 目標用戶與平台

- **用戶**：中學生、大專生、Maker；不假設任何 CAD 經驗
- **平台**：iPad（Safari，觸控優先）與 MacBook（桌面瀏覽器）；同一套響應式介面
- **語言**：繁體中文 / 英文雙語切換（i18n 架構），零件名稱保留英文原名
- **主題**：現代化 light theme

## 3. 核心工作流

1. 建立專案 → 從底部零件庫抽屜拖入電子零件到 3D 畫布
2. 排好零件相對位置（格點吸附 + 孔位磁吸）
3. 點「產生外殼」→ 設定壁厚、盒型、圓角 → 系統自動產生殼體、支柱、螺絲孔、接口開孔
4. 用基本形狀 + 孔模式（boolean）微調
5. 匯出 STL / 3MF 給切片軟體列印

## 4. 系統架構

全前端 SPA，無後端，支援離線。四層：

| 層 | 內容 |
|---|---|
| UI 層 | React + react-three-fiber：3D 畫布、懸浮工具列、零件庫抽屜、浮動屬性卡片 |
| 應用層 | Zustand：文件模型（參數化場景樹）、指令系統（undo/redo）、外殼生成器 |
| 幾何層 | `GeometryKernel` 介面，跑在 Web Worker；第一版以 manifold-3d WASM 實作 |
| 資料與輸出 | 零件庫 JSON 定義、IndexedDB 專案儲存、`.nexcad` 專案檔匯出/匯入、STL/3MF 匯出 |

關鍵決策：

- **幾何運算在 Web Worker**：boolean 為 CPU 密集，隔離到 Worker 確保 iPad 上觸控與視角操作永遠流暢。UI 與 Worker 之間以結構化訊息（節點樹進、mesh 出）通訊。
- **參數化場景樹**：文件儲存「參數 + 操作」而非 mesh。好處：非破壞性編輯、無限復原、檔案小、日後可換幾何引擎而不改文件格式。
- **`GeometryKernel` 抽象**：第一版用 Manifold（快、輕、保證封閉 mesh）；介面預留日後接 OpenCascade（STEP 匯出、真 B-rep 圓角）。
- **零件是資料不是模型**：3D 外觀由程式從 JSON 定義生成，不依賴外部 mesh 檔。

## 5. 技術棧

- React 18 + TypeScript + Vite（SPA）
- three.js + react-three-fiber + drei（渲染、控制器、gizmo）
- manifold-3d（WASM，於 Web Worker 中執行 boolean 與 primitive 生成）
- Zustand（狀態管理）+ 指令模式實作 undo/redo
- Tailwind CSS（UI 樣式）
- idb（IndexedDB 封裝）
- i18next（雙語）
- Vitest（單元測試）、Playwright（冒煙測試）

## 6. 文件模型（場景樹）

- 文件 = 節點列表 + 全域設定（單位固定 mm、格點大小）
- 節點類型：
  - `primitive`：方體、圓柱、球、圓錐、管、文字（含參數）
  - `part`：零件庫實例（引用零件 id + 覆寫，如顏色）
  - `enclosure`：外殼生成器輸出（參數化，可重新生成）
  - `group`：群組（合併後仍可解散）
- 每個節點：id、名稱、transform（位置/旋轉/縮放）、`role: solid | hole`、鎖定/隱藏旗標
- `hole` 節點與 solid 重疊即減料（非破壞性，Tinkercad 慣例）；合併群組時求值
- 求值流程：場景樹 → Worker 內以 Manifold 求值（快取未變更節點的 mesh）→ 回傳 mesh 給 three.js 渲染
- 指令系統：每個編輯動作是一個可逆指令，堆疊實作 undo/redo（⌘Z / ⇧⌘Z）

## 7. 零件資料模型

每個零件一份 JSON（`PartDefinition`），schema 含：

- `id`、`name`（en）、`nameZh`、`category`
- `body`：板子輪廓（長寬厚）+ 主要元件簡化方塊列表（位置、尺寸），供程式生成 3D 外觀
- `mountingHoles`：`[{ x, y, diameter }]` 安裝孔
- `ports`：`[{ face, x, y, w, h, label }]` 接口位置與尺寸（USB、電源座、排針等），供外殼自動開孔
- `clearanceHeight`：元件最高點，決定殼內淨空與支柱設計
- schema 以 zod 定義並有驗證測試

### 第一版零件清單（23 項）

- **開發板**：Arduino Uno R3、Arduino Nano、ESP32 DevKit V1、Raspberry Pi 4B、Raspberry Pi Zero 2 W、micro:bit V2
- **感測器與顯示**：HC-SR04 超音波、OLED 0.96"（SSD1306）、LCD1602（I2C）、PIR HC-SR501、DHT22
- **動力與電源**：SG90 伺服、MG996R 伺服、TT 減速馬達、L298N 驅動板、18650×2 電池盒、9V 電池
- **小型元件**：5mm LED、12mm 按鈕、有源蜂鳴器模組、1 路繼電器模組、半尺寸麵包板（400 孔）、全尺寸麵包板（830 孔）

## 8. 外殼生成器

輸入：場景中選定的零件（含位置）＋參數卡片設定：

- 壁厚（預設 2mm）、內部淨空邊距（預設 3mm）、圓角半徑
- 盒型：底盒＋螺絲上蓋 / 滑蓋 / 開放式面板
- 支柱螺絲規格：M2 / M2.5 / M3 / 自攻

輸出（單一參數化 `enclosure` 節點）：

- 包住所有零件的殼體（含圓角）
- 每個零件安裝孔對應的支柱（standoff），高度自動計算，含螺絲導孔
- 零件接口自動投影到最近壁面開孔（含 0.4mm 列印公差）
- 上蓋連接：四角自攻螺絲柱 + 唇邊（lip）對位
- 選配：通風槽

零件移動或參數修改後可一鍵重新生成。生成邏輯為純函數（零件定義 + 位置 + 參數 → 幾何節點），可完整單元測試。

## 9. Boolean 與螺絲孔工具

- 任何形狀可切換 `solid / hole` 模式；hole 以半透明紅色顯示
- **螺絲孔工具**：點選任一面放置標準螺絲孔；內建 M2/M2.5/M3/M4 通孔、沉頭、自攻導孔尺寸表
- **孔位投影**：選零件 + 下方板件，一鍵把安裝孔投影成對齊的螺絲孔

## 10. UI / UX 設計

佈局（觸控優先懸浮式，iPad 與 MacBook 相同）：

- 3D 畫布全螢幕
- 頂部中央懸浮工具列：形狀、孔模式、螺絲孔、外殼生成、量測、匯出
- 底部零件庫抽屜：上滑展開，分類 + 搜尋，拖入畫布
- 浮動屬性卡片：隨選取出現於物件旁，顯示尺寸/位置等可編輯欄位
- 左上：專案名、復原/重做；右上：視角方塊（ViewCube）、語言切換

互動：

- 觸控：單指旋轉視角、雙指縮放平移、點選、拖曳移動；所有觸控目標 ≥ 44px
- 桌面：滑鼠 + 快捷鍵（⌘Z、⇧⌘Z、⌘D 複製、Delete）
- 吸附：1mm 格點（可調）+ 零件孔位磁吸對齊

視覺（現代 light theme）：

- 近白畫布 + 淡格線地面；物件柔和材質色
- 懸浮面板：白底、大圓角、細邊框、輕陰影
- 單一品牌強調色（工具啟用、選取外框、主要按鈕）
- 無深色模式（v1 非目標）

## 11. 儲存與匯出

- 自動儲存：編輯後 debounce 數秒寫入 IndexedDB；專案列表頁管理多專案
- 專案檔：`.nexcad`（JSON）匯出/匯入，用於備份與分享
- 列印匯出：STL（binary）與 3MF；匯出前顯示尺寸摘要與最小壁厚警告（<1mm）

## 12. 錯誤處理

- boolean 求值失敗：保留前一有效 mesh，顯示非阻斷提示，文件不損壞
- Worker 崩潰：自動重啟並從場景樹重新求值
- 開啟時偵測 WebGL2 / WASM，不支援則顯示清楚訊息
- 匯出保證：Manifold 輸出天生封閉（watertight），另加壁厚檢查警告

## 13. 測試策略

- 幾何層、外殼生成器、孔位投影：Vitest 單元測試（純函數）；驗證支柱座標、開孔位置、mesh 體積與封閉性
- 文件模型與指令系統：undo/redo 正確性
- 零件庫：zod schema 驗證每個零件定義
- UI：Playwright 冒煙測試（建專案 → 放零件 → 產生外殼 → 匯出 STL）

## 14. 非目標（v1 不做）

- 雲端帳號與同步（日後以 Supabase 擴充）
- STEP 匯出 / OpenCascade 核心（`GeometryKernel` 已預留）
- 草圖拉伸式參數化建模
- 協作 / 分享連結
- 深色模式
- 電路模擬或接線檢查

## 15. 未來擴充方向
